# 自动化内容矩阵 · 每天 15 分钟

> 把「选题 → 初稿 → 排版 → 成品」全部交给服务器，你只做审核精修 + 手动发布。

---

## 零、内容真实性说明（先看这条）

这套系统**绝不编造正文**。稿件有两种模式，页面上会明确标注：

| 模式 | 触发条件 | 内容来源 |
| --- | --- | --- |
| **真实素材卡** | 没配 AI key（默认） | 标题、摘要、热度、原文链接全部来自真实热榜接口，正文只是事实陈述 + 来源标注，没有一个字是编的 |
| **AI 改写** | 配了 AI key | AI 只能基于抓取到的真实素材写作，提示词里硬性禁止编造数字/人名/时间/事件，文末标注信息来源；AI 调用失败时自动降级回真实素材卡 |

> 旧版的固定套话模板（"最有效的办法往往是先建立节奏"那种）已彻底删除。
> 那种内容对每个选题都一样，是典型的 AI 垃圾文，已被移除。

**为什么默认不配 key 也能看：** 真实素材卡本身就是可用的资讯简报——每条都能点开原文核实。配 key 是为了让 AI 在真实素材基础上加分析和解读，不是为了让内容"变真"（素材本来就是真的）。

### 配置 AI key（可选，让内容带原创分析）

**不用花钱**：默认平台是智谱 GLM-4-Flash，永久免费，手机号注册即可。

**最简单：把 key 写进项目根目录的 `.env` 文件**（已为你创建好并配好了智谱 key）：

```
ZHIPU_API_KEY=你的密钥
```

`.env` 已被 `.gitignore` 排除，不会上传 git；服务重启自动读取，**不用重启电脑或 WorkBuddy**。

也可以用系统环境变量（优先级低于进程已存在的变量，高于空值）：

```bash
export ZHIPU_API_KEY=你的密钥        # Linux/Mac
set ZHIPU_API_KEY=你的密钥           # Windows 临时
# Windows 永久：系统属性 → 环境变量 → 新建 ZHIPU_API_KEY
```

填了 key 后，审核页生成的就是"AI 改写"模式；不填则是"真实素材卡"模式。

**想换平台**：改 `config.py` 里的 `AI_PROVIDER` 一行即可，已预设三家：

| AI_PROVIDER | 平台 | 免费情况 | 环境变量名 |
| --- | --- | --- | --- |
| `zhipu`（默认） | 智谱 **GLM-4.7-Flash**（30B级，写作更强） | **永久免费** | `ZHIPU_API_KEY` |
| `siliconflow` | 硅基流动 + Qwen2.5-7B | 注册送 2000 万 token | `SILICONFLOW_API_KEY` |
| `deepseek` | DeepSeek | 送 500 万 token（30 天），本身极低价 | `DEEPSEEK_API_KEY` |

三家都兼容 OpenAI 接口，代码已适配好 base_url 和模型名，不用改核心代码。

**关于限流（重要）**：免费模型访问量大，`glm-4.7-flash` 常被限流（HTTP 429）。系统已内置**三级降级**：

1. 先试 `glm-4.7-flash`（写作最好，但慢、易限流）
2. 限流自动切 `glm-4-flash`（同样永久免费、不限流、快）
3. 都失败才降级到"真实素材卡"（不编造，仍可用）

所以偶发限流不影响出稿，只是那几篇质量从"AI 改写"降为"素材卡"。想完全避开限流，把 `config.py` 的 `AI_MODEL` 直接改成 `glm-4-flash` 即可（用稳定的老版）。

## 一、先把边界说清楚（重要）

这台服务器**不能**帮你做到的事，别抱幻想：

- ❌ **自动发布到平台**：头条、百家号、公众号都不给个人开放的发布 API。任何声称能自动发的，要么用群控（违规封号），要么骗你。
- ❌ **自动获得流量**：内容发出去没人看是常态，起量靠选题和积累，不靠工具。
- ❌ **全自动躺赚**：审核和发布这一步必须有人在——这恰恰是你 15 分钟的价值所在。

这台服务器**能**帮你做到的事：

- ✅ 每天定时抓选题（RSS / 关键词）
- ✅ 调用 AI 批量写初稿（你只管给一个方向）
- ✅ 自动排版成可发布的成品（Markdown + 纯文本）
- ✅ 生成一个审核后台，你打开网页就能改稿、通过、一键复制

## 三、技术架构

```
定时任务(cron)  →  pipeline.py（抓选题 → AI 写稿 → 排版）
                          ↓
                    data/queue.json（稿件队列）
                          ↓
              app.py（Flask 审核后台）→ 你精修 → 一键复制 → 手动发布
```

- 无数据库，队列用 JSON 文件，简单到能直接用记事本改。
- AI 接口走 **OpenAI 兼容格式**，可接 DeepSeek / Kimi / 通义 / 智谱，哪个便宜用哪个。
- 全部 Python 标准库 + Flask，依赖极少，4核4G 机器绰绰有余。

## 五、快速开始（本地）

```bash
# 1. 安装依赖
cd auto-content
py -3 -m pip install -r requirements.txt

# 2. 先跑 demo 模式（不需要 API key，验证全流程）
py -3 pipeline.py --demo

# 3. 启动审核后台
py -3 app.py
# 浏览器打开 http://localhost:5000
```

看到审核页里有稿件、能编辑、能一键复制，就说明整套流程通了。

## 十二、风险提示与常见坑

**风险：**
1. **API _KEY 泄露**：`config.py` 含密钥，若传 GitHub 会被爬虫扫走刷爆账单。服务器部署后设 `chmod 600 config.py`。
2. **队列文件并发**：网页生成和 cron 同时写可能冲突。已加锁保护网页端；cron 与网页偶发同时触发仍可能丢一篇，量小可忽略，量大应换 SQLite。
3. **AI 胡编**：AI 会编造数据和案例，**发布前必须人工核对**——这是你 15 分钟里最重要的事。
4. **平台限流**：纯 AI 稿容易被限流，务必精修、加真实细节。
5. **无鉴权**：审核后台目前裸奔（只有你能访问的内网/本机才安全）。**公网部署必须加密码或 IP 白名单**，否则任何人都能改你的稿。

**常见坑：**
- 网页点「生成」没反应 → 看终端有没有报错，多半是依赖没装或 key 格式错。
- 生成的稿全是"AI 生成失败" → key 填错或余额不足，看终端报错信息。
- 预览页文字带 `<h2>` 标签 → 说明正文里混了未渲染的 HTML，检查 AI 输出格式。
- 5000 端口被占用 → 改 `config.py` 的 `APP_PORT`。

## 十三、选题来源说明（热榜）

选题不是写死的，走**混合策略**，优先级如下：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 实时热榜 | 头条热榜 + 百度热搜，抓真实热度值 |
| 2 | 领域过滤 | 用 `KEYWORDS_STRONG/WEAK` 给热榜话题打分，只留相关的 |
| 3 | RSS 源 | 热榜不够时补充（在 `TOPIC_SOURCES` 配置） |
| 4 | 领域词库 | 以上都不够时用 `FALLBACK_TOPICS` 保底 |

**关键提醒**：全网热榜 90% 是大众话题（APEC、明星、体育），与你"守护父母"的垂直领域不相关。实测 102 条热榜只有 8 条命中领域词，其中真正能用的 3-4 条。所以**纯热榜不可行**，必须靠领域过滤 + 词库保底。审核页每篇稿件会标注来源和热度值，一眼看出是热榜还是保底词。

 `hot_topics.py` 负责抓榜和打分，失败自动降级，不影响主流程。

## 十五、微信推送 + 手机审核（定时推到微信）

**能做到什么**：服务器每天定时生成稿件 → 自动推送到你的微信 → 你点链接打开手机审核页 → 在手机上改稿、通过、复制成品。

**做不到什么**：微信消息卡片本身不能变成"通过/拒绝"按钮（微信不开放这种交互），所以要多点一次链接进网页。这是正规且稳定的做法。

### 15.1 申请 Server酱 key（2 分钟）

1. 打开 `sct.ftqq.com`，微信扫码登录
2. 复制 SendKey（`SCT` 开头那串）
3. **微信关注"方糖"服务号**（不关注收不到消息！这是最常见的坑）
4. 填进 `.env` 的 `SERVERCHAN_KEY=`

免费版每天 5 条，每天推 1 次完全够。想每篇单独推一条（每天 200 条）就用 PushPlus。

### 15.2 配置审核页地址和密码

在 `.env` 填：

```
APP_PASSWORD=你的密码          # 审核页密码，公网必填
REVIEW_URL=https://你的域名/?pwd=你的密码
```

`REVIEW_URL` 就是推送消息里的链接——带密码，点开直接进审核页，不用再输。
没域名先用 `http://服务器IP/?pwd=你的密码` 也行（建议尽快上 HTTPS）。

> **为什么必须设密码**：审核页公网暴露后，任何人都能点"生成/删除"，不设密码等于裸奔。

### 15.4 定时自动推送

部署脚本已配好：每天 8:00 自动跑 `daily_job.py`（生成 + 推送一条龙）。
想改时间，在服务器上 `crontab -e` 改这行：

```
0 8 * * * cd /opt/auto-content && .venv/bin/python daily_job.py >> data/cron.log 2>&1
```

（前面 `0 8` 表示每天 8:00，改成 `0 9` 就是 9 点。）

### 15.5 手机审核体验

审核页已做手机适配：看板两列、按钮加大、输入框 16px（防 iOS 自动缩放）。
流程：微信收到推送 → 点链接 → 输一次密码（链接带 pwd 则免输）→ 选稿件 → 改稿 → "保存并通过" → "预览成品"或"复制成品" → 粘贴到目标平台发布。
